# 경관 후보 데이터 출처·검수 정책

> 확인일: 2026-11-07
>
> 목적: 실제 장소를 추천 DB에 넣기 전에 출처, 이용허락 범위, 좌표와 경관 적합성을 추적한다.

## 1. 공식 근거와 현재 판단

| 공식 자료 | 확인 내용 | 프로젝트 판단 |
|---|---|---|
| [공공데이터포털 전국관광지정보표준데이터](https://www.data.go.kr/data/15021141/standard.do) | 관광지명, 소개, 위도·경도 등을 제공하며 2026-11-07 확인 당시 메타데이터에는 897건과 `이용허락범위 제한 없음`으로 표시 | 초기 후보 탐색 자료로 검토 가능. 관광지라는 사실만으로 드라이브 경관 후보로 확정하지 않음 |
| [공공데이터포털 이용정책](https://www.data.go.kr/ugs/selectPortalPolicyView.do) | 제3자 권리가 포함된 데이터는 권리자의 이용허락 범위를 확인해야 하며 공공누리 유형으로 조건을 표시 | 데이터셋별 이용허락 표시와 제3자 권리 여부를 검수 기록에 남김 |
| [공공누리 유형 안내](https://www.kogl.or.kr/info/faqList.do?cPage=1&dataGroup=2&mstIdx=KOGL_005) | 유형에 따라 출처표시, 상업적 이용, 변경 허용 범위가 달라짐 | 최종 앱의 이용 형태와 맞지 않는 유형은 별도 허락 전까지 사용하지 않음 |

`전국관광지정보표준데이터`는 좌표가 있는 후보 원천일 뿐입니다. 원천의 `관광지구분`은 행정상 `관광지`·`관광단지`를 구분하는 값이며 도시·산·바다 같은 경관 분류가 아닙니다. 실제 주행 중 풍경이 보이는지, 자동차 접근이 가능한지, 테마가 맞는지, 최신 좌표인지까지 보장하지 않으므로 이름·소개·좌표를 참고해 프로젝트 테마를 별도로 판정하고 수동 검수를 통과해야 합니다.

## 2. VERIFIED 전환 필수 조건

다음 항목을 모두 확인한 후보만 `VERIFIED`로 전환합니다.

1. 원본 제공기관 또는 자료명(`source_name`)
2. 검수 당시 원본 URL 또는 문서 식별자(`source_reference`)
3. 이용허락 범위와 필요한 출처표시 기록(`usage_rights_note`)
4. 검수 완료 시각(`verified_at`)
5. WGS84 위도·경도
6. 도시·산·강·호수·바다·공원 중 하나의 테마 수동 검수
7. 자동차로 접근할 수 있는 경유지인지 확인
8. `scenic-quality-rubric.md`의 세 품질 항목이 모두 3점 이상이고 점수 근거가 기록됨

전화번호, 담당자 이름, 개인 계정, 실제 사용자의 위치·이동 이력은 후보 데이터로 수집하지 않습니다.

## 3. DB 적용 규칙

- Flyway V3는 출처·이용권한·검수 시각 열을 추가합니다.
- 새 `VERIFIED` 행은 네 가지 출처 이력이 없으면 DB 제약으로 저장을 거부합니다.
- 과거 V2 DB에 출처 없이 존재할 수 있는 `VERIFIED` 행 때문에 V3·V4 도입 당시 제약은 `NOT VALID`로 추가했습니다.
- Flyway V6는 출처 또는 품질 근거가 불완전한 과거 VERIFIED 행을 삭제하지 않고 `PENDING`으로 전환한 뒤 두 제약을 전체 검증합니다.
- 정상 VERIFIED 행은 유지되며, PENDING으로 전환된 행은 근거를 보완하고 다시 검수하기 전까지 추천에 사용되지 않습니다.
- Flyway V4는 세 품질 점수와 검수 근거를 추가하며 3점 미만 후보가 VERIFIED로 저장되지 않게 합니다.
- Flyway V6는 `ck_spot_verified_provenance`, `ck_spot_verified_quality`를 PostgreSQL 전체 검증 상태로 전환합니다.
- 실제 후보는 `candidate-import` 프로필과 Git 제외 로컬 JSON을 사용해 등록합니다. 가져오기 전에 전체 파일을 검증하고 한 트랜잭션으로 저장하며 후보명·출처·참조가 같은 행은 중복 제외합니다.
- 로컬 등록 파일의 작성·실행 절차는 `scenic-candidate-import.md`를 따릅니다.

## 4. 서울·수도권 초기 로컬 검수 묶음

- MVP 지역은 서울·경기·인천으로 확정했습니다.
- 공식 원천 897건에서 서울·경기·인천 147건을 후보군으로 분리하고, 최초 테마별 2건씩 10건을 만든 뒤 산·강·호수 후보를 1건씩 보강해 총 13건의 PoC 묶음으로 확장했습니다.
- 로컬 JSON은 `backend/local-data/scenic-candidates.json`에 있으며 Git에서 제외합니다. 저장소에는 장소명·좌표·출처 원문을 커밋하지 않습니다.
- PostgreSQL 17에서 확장된 13건의 dry-run과 실제 등록을 확인했고 파일·DB 중복은 0건이었습니다. 최초 10건 묶음은 재실행 시 10건 모두 중복 제외되는 것도 별도로 확인했습니다.
- 이 묶음은 공개 원천과 데스크 검수에 기반한 초기 후보입니다. 실제 차량 접근성, 주행 중 경관 노출, 도로 통제와 순환 품질은 TMAP 성공 응답과 에뮬레이터·현장 검수 전까지 최종 확정하지 않습니다.

## 5. 현재 제외 사항

- 실제 관광지·경관 좌표는 Git 저장소에 넣지 않고 로컬 검수 파일로만 관리합니다.
- 외부 지도 API 응답을 후보 원천으로 영구 저장하지 않습니다.
- Free TMAP 상품 활성화 후 2026-11-07 실제 일반 자동차·다중 경유지 요청의 LIVE 처리를 확인했습니다. 다만 실제 차량 접근성과 주행 중 경관 품질은 아직 검증하지 못했습니다.
- 최종 사용 데이터가 정해지면 앱·README에 필요한 출처표시 문구를 별도로 확정합니다.

## 6. 더 넓은 후보 원천 제안 (미구현)

관광지 표준데이터 한 종류를 DB에 계속 추가하는 방식만으로는 사용자가 비교할 만큼 넓은 선택지를 만들기 어렵습니다. 다음 원천을 역할별로 조합하는 방안을 제안하며, 실제 연동 전 API 권한과 이용조건을 다시 확인합니다.

| 원천 | 적합한 역할 | 확인된 한계 |
|---|---|---|
| [TMAP 주변 POI 카테고리 검색](https://tmap-skopenapi.readme.io/reference/%EB%AA%85%EC%B9%ADpoi-%EC%A3%BC%EB%B3%80-%EC%B9%B4%ED%85%8C%EA%B3%A0%EB%A6%AC-%EA%B2%80%EC%83%89) | 현재 위치 주변 `공원`, `주요시설물`, `문화시설`, `공연장` 등을 실시간 후보로 조회. 반경 1~33km, 응답 최대 200건 지원 | 산·바다·강·호수·랜드마크 전용 카테고리는 없음. TMAP 응답은 24시간 이상 저장하지 않음 |
| [한국관광공사 국문 관광정보 서비스](https://www.data.go.kr/data/15101578/openapi.do) | 위치·지역·키워드·분류 기반의 전국 관광 콘텐츠와 소개·이미지로 도시 랜드마크 후보를 보강 | 개발계정은 일 1,000건이며 운영은 심의 승인. 관광 콘텐츠이므로 모든 생활 POI를 포함하지 않음 |
| [전국도시공원정보표준데이터](https://www.data.go.kr/data/15012890/standard.do) | 공원명·공원구분·면적·시설·좌표를 이용한 공원 후보 보강 | 공원에 특화되어 다른 테마에는 사용할 수 없음 |

권장 구조는 `동적 후보 탐색 → 짧은 수명의 중복 제거·테마 태깅 → 희망 시간 기반 거리 1차 필터 → 사용자 선택 → 선택한 후보만 실제 경로 계산`입니다. 이렇게 하면 POI 목록은 넓게 보여 주면서 제한이 더 작은 경로 API 호출은 아낄 수 있습니다.

`CITY`는 TMAP에 랜드마크 또는 인기순 카테고리가 없으므로 단순 주변 POI 전체를 사용하지 않습니다. TMAP의 주요시설물·문화시설·공연장 후보와 TourAPI의 역사·건축/조형물·박물관/기념관·전망대·광장 계열을 합친 뒤, 병원·학교·주민센터·일반 상점·주차장 같은 일상 시설은 제외하고 출처 신뢰도·랜드마크 유형·대표 설명/이미지 존재·지역 내 중복·경로 적합성으로 순위를 정하는 방안을 제안합니다. 이 점수와 제외 목록은 아직 확정하지 않았습니다.
