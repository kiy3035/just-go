# 제품 요구사항 — just go (PRD v0.1)

> 상태: 2026-10-31 기준. `[확정]`과 `[제안]`을 구분한다. **앱명·프로젝트명: `just go` [확정]**.

## 1. 문제와 가치

- [확정] 목적지가 없지만 드라이브하고 싶은 사용자가 **출발 위치, 대략적인 주행 시간, 원하는 풍경**을 선택하면 적합한 운전 코스를 찾는다.
- [확정] 풍경 테마: 도시 / 산 / 강 / 호수 / 바다.
- [확정] 차량용 Android Automotive OS / Pleos Connect 앱을 Java로 개발.
- [제안] 추천 결과는 2~3개 코스로 제한하고, 코스 선택 시 차량 내장 내비게이션에 경유지/목적지를 넘긴다.
- [결정] 드라이브 기록·즐겨찾기는 핵심 기능 안정화 이후(P1)로 미룬다. 초기 MVP는 코스 추천과 내비게이션 연동에 집중한다.

## 2. 사용자 시나리오

1. 사용자: 앱을 켜고 현재 위치 사용 또는 출발지를 직접 선택한다.
2. 사용자: 왕복·편도, 희망 시간(30/60/120분 또는 직접 입력), 테마(도시/산/강/호수/바다)를 선택한다.
3. 시스템: 검수된 경관 구간/명소 후보를 탐색하고 실제 자동차 경로 API로 예상 시간·거리를 계산한다.
4. 사용자: 추천 코스의 경유 순서, 예상 시간·거리, 추천 이유를 확인한다.
5. 사용자: 시작을 선택한다. 앱이 NaviHelper를 통해 차량 내비게이션 연동을 요청한다.
6. [P1] 추후 드라이브 기록이나 즐겨찾기를 조회한다.

## 4. 동작 규칙 및 미확정 사항

- [제안] 희망 시간은 **출발지 복귀까지 포함한 총 예상 운전 시간**으로 정의; 현장 체류 시간 제외.
- [임시 PoC 기준] LIVE 목표 시간 허용 범위는 기본 -20%~+15%. 사용자가 선택한 시간보다 조금 짧은 코스는 허용하되 과도한 초과 운전은 더 보수적으로 제한하며 환경변수로 조정 가능.
- [결정] 서울·수도권 일부 지역의 수동 검수된 경관 코스로 MVP 시작.
- [필수 검증] 코스 경유지를 차량 내비에 넘겨도 외부 지도 API가 계산한 정확한 도로 형태가 보장되지 않을 수 있음.
- [필수 검증] Pleos Emulator에서 현재 위치 접근, NaviHelper 목적지/경유지 전달, 백그라운드 이벤트 지원 여부.
- [결정] 목표 앱 카테고리는 **Mobility Services**. [필수 검증] 실제 등록·심사 적합성은 아직 검증되지 않음.
- [결정] 첫 외부 자동차 경로 PoC는 TMAP API Free를 사용. Free TMAP 상품 활성화 후 실제 일반 자동차·다중 경유지 LIVE 처리를 검증했으며 원시 응답은 영구 저장하지 않음.
- [임시 개발 기준] `ROUND_TRIP`의 희망 시간은 출발지 복귀까지, `ONE_WAY`는 종료 지점 도착까지의 총 운전 시간으로 해석.
- [임시 PoC 정책] 품질 우선순위가 높은 후보 두 곳의 단일 경로 2건과 두 곳을 잇는 조합 경로 1건을 TMAP으로 계산함. `ROUND_TRIP` 조합은 두 후보를 순서대로 경유해 출발지로 복귀하고, `ONE_WAY` 조합은 첫 후보를 경유해 마지막 후보에서 종료함.
- [구현] TMAP 외부 요청 직전에 서울 날짜별 호출권을 PostgreSQL에서 원자적으로 예약하며 기본 90건 상한을 서버 재시작·동시 요청에도 유지함. 날짜와 건수만 저장하고 앱 키·좌표·경로·응답은 저장하지 않음.
- [구현] 추천 API는 로컬에서 loopback으로만 열고 공개 `production` 환경에서는 TMAP 키와 별개의 접근 토큰을 필수화함. 클라이언트별 분당 4회·서버 동시 2회·요청 본문 8KiB 기본 제한을 일일 TMAP 상한과 함께 적용함.
- [구현] 한 추천 요청에서 일부 후보 계산이 끝난 뒤 일일 호출 한도가 소진되면 이미 확보한 LIVE 경로는 보존해 반환함. 첫 후보부터 한도가 없거나 인증·네트워크·응답 오류가 발생하면 부분 성공으로 숨기지 않고 제공자 오류로 반환함.
- [임시 PoC 구현] TMAP 호출 전 150km/h 상한을 사용해 희망 시간 내 물리적으로 도달하기 어려운 후보를 직선거리로 제외. 왕복은 복귀 시간을 고려해 편도 후보 거리 상한을 절반으로 계산하며 최종 시간 판정은 실제 자동차 경로의 설정된 시간 범위로 수행함.
- [구현] LIVE 후보는 기본 -20%~+15% 안에서 시간 차이가 작은 순, 같은 차이면 왕복 중복률·거리·경로 ID 순으로 정렬해 최대 3건 반환. 범위 안의 후보가 없으면 가짜 코스를 만들지 않고, 실제 계산 후보 시간을 5분 단위로 맞춘 가까운 대체 시간 조건을 최대 3건 반환함. 선택 테마에 검수 후보가 없으면 DB에 후보가 존재하는 다른 풍경을 최대 3개 재검색 조건으로 반환함.
- [구현] 백엔드 추천 상세는 순서·역할(`WAYPOINT`/`DESTINATION`)·이름·WGS84 좌표가 있는 지점 목록을 반환. 왕복은 경관 후보 1~2곳 다음 출발지 복귀, 편도 조합은 첫 후보 경유 후 마지막 후보 도착 순서이며 Android 표시·NaviHelper 전달은 별도 검증 필요.
- [구현] `VERIFIED` 경관 후보는 원본 제공기관·참조 주소·이용허락 검토·검수 시각과 세 품질 점수 근거를 모두 가져야 함. V6에서 불완전한 과거 행을 삭제하지 않고 `PENDING`으로 전환한 뒤 전체 제약을 검증함.
- [구현] 실제 후보는 공개 쓰기 API 없이 명시적 `candidate-import` 프로필에서만 로컬 JSON으로 등록. 전체 파일 선검증·트랜잭션·중복 제외를 적용하고 실제 파일은 Git에서 제외함.
- [임시 PoC 구현] 테마 적합성·풍경 품질·경유지 적합성을 각각 1~5점으로 수동 평가. 세 항목이 모두 3점 이상인 VERIFIED 후보만 합계가 높은 순으로 외부 경로 계산에 전달함.
- [임시 PoC 구현] TMAP 다중 경유지 GeoJSON 선형에서 같은 무방향 선분의 재통과 거리 비율을 계산하고, 시간 차이가 같은 왕복 후보는 중복률이 낮은 순으로 정렬함. 원시 선형은 저장하지 않으며 편도·형상 없는 응답은 `null`로 구분함.
- [미검증] 실제 TMAP 응답 분포·실주행을 바탕으로 한 중복률 상한과 최종 순환 품질 가중치. 현재 후보 품질·시간·중복률 정렬 완료가 최종 추천 알고리즘 전체 완료를 의미하지 않음.
- [미정] 익명 계정·로그인 여부, 코스 저작권/사용권, 직접 입력 시간 범위의 최종값.

## 5. 비기능 요구사항

- 운전 중 복잡한 조작 없이 사용. 코스 탐색·세부 입력은 정차 상태에서 제공하며 실제 Pleos UX 정책을 검증.
- 외부 경로 API 호출 실패 시 제한 시간 내 오류 안내 및 재시도 가능 상태 유지.
- API 키, 차량/개인의 상세 위치 이력, 인증 토큰 보호. 불필요한 운행 궤적 영구 보관 금지.
- 개발 모드의 Mock 응답은 명확하게 표시하고, 실제 추천 결과로 오인시키지 않는다.
- 서버는 Android 앱 및 외부 API와 HTTPS 통신할 수 있게 추후 배포 가능하도록 설계. **초기 AWS 배포는 하지 않음.**

## 6. 공모전 제출 및 시연

- 공식 접수 마감: **2026-11-15** (변경 가능하므로 제출 직전 재확인).
- **1차 필수:** 접수양식/기획서 및 필요한 동의/서명.
- **1차 선택·가산점:** 시연 영상, GitHub(소스+APK 포함) 등 개발 산출물. GitHub를 제출한다면 `apk/` 등 별도 경로에 실제 빌드한 APK를 포함하도록 공식 지침 확인.
- 실제 차량은 없어도 됨. **Pleos Emulator 화면 녹화로 시연 영상을 제작**하는 것을 목표로 한다.
- **2차 PT 심사:** 실제 동작 앱의 에뮬레이터 또는 기기 시연 필수. 1차 영상만으로 2차 실시간 시연을 대체한다고 가정하지 않는다.
- 영상 녹화 시나리오: 조건 선택 → 실제 추천 결과 → 상세 → 내비 연동(검증 가능 구간만) → 선택적으로 기록 화면.

## 7. 2인 역할

- **김인영 (개발환경·서버 리드):** 프로젝트 전체 툴 설치와 개발환경 세팅, Spring Boot, MyBatis, PostgreSQL, 추천 엔진, 외부 API, 인프라, 관측. Android Studio, Android SDK, Pleos Emulator 등 Android 측 개발 도구의 설치·공통 환경 구성도 담당한다.
- **정도혜 (UI/UX·프론트·Android 리드):** 준비된 개발환경에서 UI/UX, Android Java, XML 화면, 프론트 로직, 앱 측 API 연동, Pleos 앱 기능, 에뮬레이터 화면 검증과 앱 빌드.
- **공동:** API 계약, 코스·경관 검수, 보안·시연 정책, 통합 테스트, 제출물.
