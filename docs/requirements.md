# 제품 요구사항 — just go (PRD v0.1)

> 상태: 2026-10-31 기준. `[확정]`과 `[제안]`을 구분한다. **앱명·프로젝트명: `just go` [확정]**.

## 1. 문제와 가치

- [확정] 목적지가 없지만 드라이브하고 싶은 사용자가 **출발 위치, 대략적인 주행 시간, 원하는 풍경**을 선택하면 적합한 운전 코스를 찾는다.
- [확정, 2026-11-07 사용자 지시] 화면 선택은 어디든 / 도시 / 산 / 바다 / 강·호수 / 공원. 기본값은 왕복·60분·어디든. 출발지는 기기의 현재 위치를 사용한다.
- [확정] 차량용 Android Automotive OS / Pleos Connect 앱을 Java로 개발.
- [확정] 추천 결과는 유효 코스 3~5개 확보를 목표로 하고 최대 10개까지 표시한다. 코스를 선택한 뒤 상세 화면의 시작 버튼으로 차량 내비에 전달한다.
- [결정] 드라이브 기록·즐겨찾기는 핵심 기능 안정화 이후(P1)로 미룬다. 초기 MVP는 코스 추천과 내비게이션 연동에 집중한다.

## 2. 사용자 시나리오

1. 사용자: 앱을 켜고 현재 위치 사용 또는 출발지를 직접 선택한다.
2. 사용자: 왕복·편도, 희망 시간(30/60/120분 또는 직접 입력), 테마(어디든/도시/산/바다/강·호수/공원)를 선택한다.
3. 시스템: 검수된 경관 구간/명소 후보를 탐색하고 실제 자동차 경로 API로 예상 시간·거리를 계산한다.
4. 사용자: 추천 코스의 경유 순서, 예상 시간·거리, 추천 이유를 확인한다.
5. 사용자: 시작을 선택한다. 앱이 NaviHelper를 통해 차량 내비게이션 연동을 요청한다.
6. [P1] 추후 드라이브 기록이나 즐겨찾기를 조회한다.

## 4. 동작 규칙 및 미확정 사항

- [확정] 희망 시간은 편도 도착 또는 왕복 복귀까지의 예상 운전 시간으로 정의하며 현장 체류 시간은 제외함.
- [구현] LIVE 계산이 성공해도 희망 시간 ±15%를 벗어난 경로는 제외하고, 범위 안의 결과가 없으면 시간·풍경 조건 변경을 안내함.
- [구현] `public-data,tmap` 프로필에서 전국도시공원정보표준데이터·TourAPI·TMAP 주변 POI와 DB 보정 후보를 병합·중복 제거해 최대 50건을 반환. 외부 원천을 우선하고 DB는 정규화 이름이 같고 검수 좌표 1km 이내인 동일 장소의 수동 분류 보정·제외와 외부 장애 fallback에 사용함.
- [구현] 원천이 제공한 공식 분류만 제품 테마에 명시적으로 매핑하며 장소 이름으로 테마를 추측하지 않음. 도시공원 원천은 `PARK`, TourAPI는 공식 `lclsSystmCode2/3`, TMAP POI는 공식 요청 카테고리(`공원`, `주요시설물`, `문화시설`, `공연장`)를 따름. 매핑할 수 없는 항목은 제외함.
- [구현] `ANYWHERE`는 외부·DB 후보를 도시·산·강·호수·바다·공원 순환 방식으로 채우고 `WATER`는 강·호수를 번갈아 채움. DB와 외부 원천의 정규화 이름이 같고 좌표가 1km 이내이면 수동 보정된 DB 후보가 외부 후보를 대체함.
- [구현] 같은 실제 테마 안에서도 데이터 원천을 순환해 CITY가 TMAP 시설만으로, PARK가 한 공원 원천만으로 채워지지 않게 함. 각 원천 내부에서는 공식 분류 우선순위와 거리를 유지함.
- [구현] Android는 선택 조건으로 계산된 추천 코스를 먼저 받음. 기존 호환용 장소 토큰은 30분 동안 공개 장소 좌표만 보관하며, 해당 요청은 선택한 한 곳을 계산함.
- [구현] 같은 위치·반경에서 테마만 바꾼 TourAPI 후보는 SHA-256 해시 키로 기본 10분·최대 64개 메모리 캐시를 사용하고, 동시에 들어온 동일 범위 조회도 하나의 광역 API 작업을 공유함. 원시 출발 좌표와 외부 원시 응답은 캐시 키·로그·DB에 저장하지 않음.
- [구현] TourAPI는 원점과 육각 링 중심을 기본 최대 13곳 조회함. 자동 추천에서는 검색 반경이 커질 때 링 간격도 넓혀 더 먼 지역을 조회하며, 콘텐츠 ID로 중복을 제거함.
- [결정] 최종 통합과 화면 캡처는 김인영 PC 한 대에서 DB·백엔드·Android Studio·Pleos Emulator를 모두 실행함. 정도혜는 프론트 코드만 Git으로 전달하고 API 키·환경변수 파일은 공유하지 않음.
- [결정] 초기 관광지 표준데이터 13건은 원천의 행정상 관광지 구분을 프로젝트 풍경 테마로 수동 해석한 PoC였으므로 제거함. 장소 DB는 외부 원천 복제본이 아니라 수동 보정·제외·fallback 용도로 유지함.
- [필수 검증] 코스 경유지를 차량 내비에 넘겨도 외부 지도 API가 계산한 정확한 도로 형태가 보장되지 않을 수 있음.
- [필수 검증] Pleos Emulator에서 현재 위치 접근, NaviHelper 목적지/경유지 전달, 백그라운드 이벤트 지원 여부.
- [결정] 목표 앱 카테고리는 **Mobility Services**. [필수 검증] 실제 등록·심사 적합성은 아직 검증되지 않음.
- [결정] 첫 외부 자동차 경로 PoC는 TMAP API Free를 사용. Free TMAP 상품 활성화 후 실제 일반 자동차·다중 경유지 LIVE 처리를 검증했으며 원시 응답은 영구 저장하지 않음.
- [임시 개발 기준] `ROUND_TRIP`의 희망 시간은 출발지 복귀까지, `ONE_WAY`는 종료 지점 도착까지의 총 운전 시간으로 해석.
- [구현] 자동 추천은 목적지별 경로를 계산하고, 왕복은 가는 길과 복귀 길을 따로 조회해 합산함.
- [구현] TMAP 외부 요청 직전에 서울 날짜별 호출권을 PostgreSQL에서 원자적으로 예약하며 기본 90건 상한을 서버 재시작·동시 요청에도 유지함. 날짜와 건수만 저장하고 앱 키·좌표·경로·응답은 저장하지 않음.
- [구현] 동일 출발지·목적지·경유지 순서의 성공 경로는 기본 10분 동안 거리·시간·중복률 요약만 메모리에서 재사용하고, 동시에 들어온 동일 경로 요청은 외부 호출 한 건을 공유함. 캐시 키는 좌표 조합의 SHA-256 해시이며 원시 좌표·경로 선형은 저장하지 않고 서버 재시작 시 제거함.
- [구현] 추천 API는 로컬에서 loopback으로만 열고 공개 `production` 환경에서는 TMAP 키와 별개의 접근 토큰을 필수화함. 클라이언트별 분당 4회·서버 동시 2회·요청 본문 8KiB 기본 제한을 일일 TMAP 상한과 함께 적용함.
- [구현] 한 추천 요청에서 일부 후보 계산이 끝난 뒤 일일 호출 한도가 소진되면 이미 확보한 LIVE 경로는 보존해 반환함. 첫 후보부터 한도가 없거나 인증·네트워크·응답 오류가 발생하면 부분 성공으로 숨기지 않고 제공자 오류로 반환함.
- [구현] 희망 시간과 주행 방식, 최대 평균속도 100km/h로 기본 직선거리 반경을 정하고, 유효 경로를 확보하기 위해 최대 세 단계까지 넓힘. 실제 추천은 목표 시간 ±15% 안에서 TMAP 예상 주행시간의 차이로 정함.
- [구현] TMAP 거리·시간으로 계산한 평균속도가 5km/h 미만 또는 130km/h 초과인 비정상 조합은 추천에서 제외함.
- [구현] 최대 10건까지 반환하며 선택한 풍경에서 유효 경로가 없으면 실제 계산된 다른 풍경 코스를 별도 표시함. 도시 추천은 관람 가능한 행사를 일반 명소보다 앞에 표시함.
- [구현] 추천 상세에는 지점별 역할(`WAYPOINT`/`DESTINATION`)과 좌표, 각 지점까지의 TMAP 예상 구간 시간이 포함됨. 기존 Android 단일 목적지 전달은 확인됐으며 변경된 추천 흐름의 Pleos 검증은 별도 진행이 필요함.
- [구현] `VERIFIED` 경관 후보는 원본 제공기관·참조 주소·이용허락 검토·검수 시각과 세 품질 점수 근거를 모두 가져야 함. V6에서 불완전한 과거 행을 삭제하지 않고 `PENDING`으로 전환한 뒤 전체 제약을 검증함.
- [구현] 실제 후보는 공개 쓰기 API 없이 명시적 `candidate-import` 프로필에서만 로컬 JSON으로 등록. 전체 파일 선검증·트랜잭션·중복 제외를 적용하고 실제 파일은 Git에서 제외함.
- [임시 PoC 구현] 테마 적합성·풍경 품질·경유지 적합성을 각각 1~5점으로 수동 평가. 세 항목이 모두 3점 이상인 VERIFIED 후보만 합계가 높은 순으로 외부 경로 계산에 전달함.
- [임시 PoC 구현] TMAP 다중 경유지 GeoJSON 선형에서 같은 무방향 선분의 재통과 거리 비율을 계산하고, 시간 차이가 같은 왕복 후보는 중복률이 낮은 순으로 정렬함. 원시 선형은 저장하지 않으며 편도·형상 없는 응답은 `null`로 구분함.
- [미검증] 실제 TMAP 응답 분포·실주행을 바탕으로 한 중복률 상한과 최종 순환 품질 가중치. 현재 후보 품질·시간·중복률 정렬 완료가 최종 추천 알고리즘 전체 완료를 의미하지 않음.
- [미정] 익명 계정·로그인 여부, 코스 저작권/사용권, 직접 입력 시간 범위의 최종값.

## 5. 비기능 요구사항

- 운전 중 복잡한 조작 없이 사용. 코스 탐색·세부 입력은 정차 상태에서 제공하며 실제 Pleos UX 정책을 검증.
- 외부 경로 API 호출 실패 시 제한 시간 내 오류 안내 및 재시도 가능 상태 유지.
- API 키, 차량/개인의 상세 위치 이력, 인증 토큰 보호. 불필요한 운행 궤적 영구 보관 금지.
- 개발 모드의 Mock 응답은 명확하게 표시하고, 실제 추천 결과로 오인시키지 않는다.
- 서버는 Android 앱 및 외부 API와 HTTPS 통신할 수 있게 추후 배포 가능하도록 설계. **초기 AWS 배포는 하지 않음.**
