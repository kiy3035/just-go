# just go 프로젝트 진척 현황

> 마지막 갱신: 2026-11-09
> 이 문서는 완료·보류·차단 항목을 한눈에 확인하는 현황판입니다. 상세 실행 기록은 [`setup-report.md`](setup-report.md), 제품 범위는 [`requirements.md`](requirements.md), API 계약은 [`api-contract.yaml`](api-contract.yaml)을 기준으로 합니다.

## 상태 기준

- `완료`: 코드 또는 환경 구성을 끝내고 가능한 검증을 실제로 통과함
- `진행 가능`: 선행 결정 없이 바로 이어서 작업할 수 있음
- `보류`: 사용자 지시로 현재 순서를 미룸
- `차단`: 장비·계정·비용 승인·제품 결정 등 선행 조건이 필요함
- `미착수`: 아직 작업하지 않음

## 완료된 백엔드 흐름

```text
추천 HTTP 요청
  → RouteRecommendationService
  → VERIFIED 경관 장소 후보 조회
  → 출발지·희망 시간 기반 직선거리 상한 적용
  → DrivingRouteProvider 요청 모델로 후보 전달
  → mock 프로필: MOCK 응답
  → tmap 프로필: PostgreSQL 일일 호출권 예약 후 단일 경로 2건+두 후보 조합 1건 계산
  → 후보 계산 중 한도 소진 시 앞에서 확보한 LIVE 경로를 보존하고 추가 호출 중단
  → TMAP 시간·거리와 왕복 선분 중복률 LIVE 응답
  → LIVE 코스별 WAYPOINT/DESTINATION 순서 반환
  → 기본 프로필: UNAVAILABLE 응답
```

넓은 후보 선택 흐름은 `후보 GET → 공원 API·TourAPI·TMAP POI·DB 보정 후보 병합/거리 필터 → 30분 토큰 → 선택 토큰을 추천 POST → 선택 장소 한 곳만 TMAP 경로 계산`입니다. 외부 후보 원천 일부가 실패하면 정상 후보는 유지하고 `partial=true`, `unavailableSources`로 실패 원천을 함께 반환합니다. TMAP POI 조회와 자동차 경로 계산은 서로 다른 API입니다.

현재 `MOCK` 결과는 화면·REST 연결 확인 전용 가짜 예시이며 실제 도로 경로, 시간, 거리로 간주하지 않습니다. `LIVE` 경로는 실제 Free TMAP 일반 자동차·다중 경유지 요청으로 성공 처리를 확인했습니다. 기본 프로필은 외부 제공자가 없으므로 실제 코스를 만들지 않습니다.

## 건너뛰거나 미룬 작업

1. Android 추천 결과 선택 화면의 실제 LIVE 데이터·Automotive 반응형 검증
2. CarUxRestrictions 구현의 실제 주행 상태 전환 검증
3. 앱의 LIVE 왕복·조합 결과에서 NaviHelper 다중 경유지 실제 호출 검증
4. 동적 원천 후보의 실제 차량 접근성·경관·순환 품질 검수
5. 실제 경로 기반 왕복 중복률·순환 품질 검수와 대체 조건 정확도 조정
6. 원격 HTTPS 배포, 고유 applicationId, Release APK와 서명

## 바로 이어갈 다음 작업

1. 실제 TMAP POI 응답과 앱 후보 모달의 `sourceCategory` 표시·선택 전달을 통합 검증한다.
2. 공식 분류로 정리된 산·바다·강/호수와 도시 후보를 실제 주행 관점에서 검수하고 명시적 제외·보정 목록을 정한다.
3. 실제 또는 에뮬레이터 주행으로 선택 후보의 접근성·경관·왕복 중복률을 검수한다.

TMAP 키는 `backend/.env`에서 정상 로딩됐고 Free TMAP 상품 활성화 후 LIVE 처리를 확인했습니다. 키·원시 응답·테스트 좌표는 문서와 로그에 저장하지 않습니다.

## 갱신 규칙

- 기능·환경 작업이 끝날 때 이 문서의 상태와 남은 조건을 함께 갱신합니다.
- 실제 실행 명령과 성공·실패 로그 요약은 `docs/setup-report.md`에 날짜순으로 남깁니다.
- API 요청·응답이 바뀌면 `docs/api-contract.yaml`을 같은 작업에서 갱신합니다.
- 개인정보·비밀값·실제 위치·API 키는 이 문서를 포함해 저장소에 기록하지 않습니다.
