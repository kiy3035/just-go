# 왕복 경로 선형 품질 기준

> 상태: 실제 TMAP 호출·주행 검증 전의 임시 PoC 기준
>
> 공식 응답 형식 확인일: 2026-11-03

## 1. 공식 응답 근거

- [TMAP 다중 경유지 안내 샘플](https://tmap-skopenapi.readme.io/reference/%EB%8B%A4%EC%A4%91-%EA%B2%BD%EC%9C%A0%EC%A7%80-%EC%95%88%EB%82%B4-%EC%83%98%ED%94%8C%EC%98%88%EC%A0%9C)은 응답 `features[].geometry`가 GeoJSON 형식이며, `LineString` 좌표는 `[경도, 위도]` 배열이라고 설명합니다. 2026-11-14 재확인 결과 경유지·도착점의 `pointType`과 직전 지점부터의 구간 초인 `time`도 공식 응답 필드로 제공됩니다.
- [TMAP 자동차 경로안내](https://tmap-skopenapi.readme.io/reference/%EC%9E%90%EB%8F%99%EC%B0%A8-%EA%B2%BD%EB%A1%9C%EC%95%88%EB%82%B4)는 `totalValue=1`이면 전체 응답, `totalValue=2`이면 총 거리·시간 등의 요약만 반환한다고 설명합니다.
- 현재 왕복은 다중 경유지 응답의 선형을 분석합니다. 편도는 요약 응답을 사용하므로 중복률을 계산하지 않습니다.
- 왕복 단일 목적지는 `출발지 → 목적지 경유 → 출발지` 다중 경유지 요청 한 번으로 계산합니다. 경유지와 도착점의 공식 구간 시간 합계가 `totalTime`과 정확히 일치할 때만 앱에 구간 시간으로 전달하고, 불일치하거나 누락되면 값을 추측하지 않습니다.

## 2. 임시 계산 방식

1. `LineString`만 사용하고 `Point`와 형식이 잘못된 좌표는 분석에서 제외합니다.
2. WGS84 좌표를 소수점 여섯 자리로 정규화합니다.
3. 두 좌표로 만든 선분은 진행 방향이 반대여도 같은 선분으로 봅니다.
4. 각 선분의 거리는 Haversine 공식으로 계산합니다.
5. 최초 통과 이후 같은 선분을 다시 지난 거리의 합을 전체 분석 거리로 나눕니다.

```text
중복 주행 비율(%) = 재통과 선분 거리 / 전체 분석 선분 거리 × 100
```

같은 길을 그대로 갔다가 돌아오면 최초 편도는 정상 구간, 복귀 편도는 재통과 구간이므로 약 50%가 됩니다. 유효한 선분이 없으면 0으로 추측하지 않고 `null`을 반환합니다.

## 3. 추천 적용 범위

- 희망 시간 차이가 같은 LIVE 후보끼리만 중복률이 낮은 왕복을 우선합니다.
- 중복률도 같으면 거리와 경로 ID 순으로 정렬합니다.
- 형상 없는 후보는 중복률을 확인한 후보 뒤에 둡니다. 편도 후보는 모두 `null`이므로 기존 거리 순서가 유지됩니다.
- 임시 지표만으로 후보를 탈락시키는 상한선은 두지 않습니다. 실제 응답 분포와 주행 검증 없이 기준값을 정하지 않습니다.

## 4. 개인정보·저장 정책

- TMAP 원시 선형 좌표는 DB, 파일 또는 로그에 저장하지 않습니다.
- 응답 처리 중 정수 백분율로 축약한 뒤 원시 좌표 객체를 유지하지 않습니다.
- 이 수치는 도로 안전, 통제, 기상, 교통이나 실제 풍경 품질을 보증하지 않습니다.
- 실제 사용자 위치·이동 이력의 수집 또는 영구 저장 기능으로 확장하지 않습니다.
